# 黑商造型结构化货架

编码: UTF-8

这里存放重建后的正式造型库存。库存分为两条线:

- `sets.md`: 完整套装货，保存整套穿搭的轮廓、层次、色块图谱、饰品系统和可拆单品。
- `items/*.md`: 单品货，保存可复用的上装、下装、鞋履、护具、饰品、材质和道具。
- `../../references/*.md`: 设计方法、操作符、裁片图案、鞋履饰品语法。正式库存应优先使用这些语法把参考洗成可复用结构。

## 核心原则

- 不把服装简化为单一颜色。
- 不写死具体色相，除非用户或职业识别明确要求。
- 使用结构色块图谱记录明度、面积、位置和作用。
- 套装货保存完整造型算法，单品货只作为拆件和补强。
- 饰品不是边角料；包具、带具、挂扣、徽章、护目镜、面罩、手套、护腕、腿包、抽绳和拉链都必须可入库。
- 基础款必须仍然可读，但每件设计至少应有一个结构变形、一个裁片路径、一个工艺边界和一个记忆点。
- 高级感不是满身细节。默认复杂度配额为: 大形体 60%、中型裁片 25%、小工艺 10%、图案符号 5%。
- 设计师方法默认匿名转译。用户明确要求测试提示词引用时，可以记录 `设计师提示引用`，但必须同时记录具体结构，不能用设计师名字代替设计。
- 鞋子必须写清鞋型原型、鞋底结构、鞋面切割、鞋口连接和重心作用；不能只写厚底鞋。
- 饰品必须说明挂点、连接方式、形状体积、身体读法和职业识别；不能只是装饰清单。

## 设计生成语法字段

新入库或升级库存时优先补充:

```yaml
基础款原型:
设计来源方法:
设计师提示引用:
设计操作:
裁片路径:
图案策略:
工艺边界:
身体适配:
复杂度配额:
失败规避:
```

其中 `设计师提示引用` 仅在用户明确允许提示词引用设计师时填写。普通库存应使用 `设计来源方法` 的匿名方法名。

## 明度词表

- 深值
- 中深值
- 中值
- 中浅值
- 浅值
- 高亮细线
- 高亮点缀
- 低亮硬质点缀

避免直接写黑、白、灰作为库存色彩规则，防止生成时被硬套成具体颜色。

滚边、包边、嵌条、衣片边缘窄饰边默认只作结构线: 使用同色系或轻微明度差，不收异色、高饱和、高亮、高对比的廉价装饰边。
