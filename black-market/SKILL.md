# 黑商

黑商只进货，不做人设。黑商从用户提供的图片、文件夹或文字货单里提取可复用视觉资产，轻洗成库存，供三宅、托尼、阿佐特等模块选用。

## 总边界

黑商可以处理:

- 造型: 套装、服装单品、鞋履、护具、饰品、小件、手持道具、材质、层次关系、结构色块。
- 眉型: 静态眉毛形状。
- 表情: 表演状态和面部动作意图。
- 姿势: 全身动作、重心、手势和道具互动。

黑商不得处理:

- 人设、身份、职业、故事、阵营、关系。
- 妆容、脸型、五官、肤色、皮肤质感、颜值判断。
- 来源角色名、作品名、文件名作为正式库存内容。

## 命令车道

支持:

```text
@黑商 造型
@黑商 造型 套装
@黑商 造型 服装
@黑商 造型 饰品
@黑商 造型 鞋履
@黑商 造型 道具
@黑商 眉型
@黑商 表情
@黑商 姿势
```

如果用户只说 `@黑商`，根据附件内容判断车道；无法判断时再问。

## 造型洗货原则

造型库存现在使用结构化货架:

```text
black-market/inventory/styling/sets.md
black-market/inventory/styling/items/outerwear.md
black-market/inventory/styling/items/tops.md
black-market/inventory/styling/items/bottoms.md
black-market/inventory/styling/items/footwear.md
black-market/inventory/styling/items/armor.md
black-market/inventory/styling/items/accessories.md
black-market/inventory/styling/items/materials.md
black-market/inventory/styling/items/props.md
```

洗造型前还应使用这些设计语法参考:

```text
black-market/references/designer-methods.md
black-market/references/design-operators.md
black-market/references/pattern-and-cutting.md
black-market/references/footwear-accessory-grammar.md
```

这些参考用于把服装、鞋履和饰品从“单品名称”提升为“设计生成语法”。默认把设计师方法转译成匿名结构语言；当用户明确要求测试设计师引用时，可以记录 `设计师提示引用` 字段供阿佐特使用，但正式库存仍必须以可见结构为主。

每张完整穿搭图默认洗两份:

1. `套装货`: 保存完整造型算法，包括轮廓、层次、色块图谱、饰品系统和可拆单品。
2. `单品货`: 拆出可复用零件，包括上装、内搭、下装、鞋履、护具、饰品、材质和手持道具。

除非用户要求只洗某一类，否则不要只产出单品。

### 造型算法与功能位

黑商洗造型时必须把参考从“衣服名称”提升成“造型算法”。不要只写衬衫、裤子、外套；要记录这套造型靠什么成立，供三宅后续替换和混搭。

每个套装货应尽量记录:

- 造型算法: 例如 `警示机能型`、`轻装装甲型`、`职业异化型`、`权力套装型`、`仪式宽体型`、`透明防护型`、`裸核束缚型`、`街头战术型`、`厨工匠人型`、`贵族改装型`、`荒野补丁型`、`冷感封闭型`、`松弛居家型`、`制服拆解型`、`机械维修型`、`黑市改造型`。可新增语义准确的算法名，但必须是可复用的穿搭方法，不是来源角色身份。
- 设计功能位: 记录哪些部位承担 `身体暴露`、`体积扩张`、`收束`、`功能挂载`、`身份标记`、`材质冲突`、`遮蔽`、`动作释放`、`仪式装饰`、`生活磨损` 等功能。
- 可替换位: 记录哪些槽位可以换成同功能单品，例如基础层、外层体积、腰部系统、腿部系统、手臂系统、头颈系统、标记系统。
- 反默认价值: 说明这套结构如何避免主视觉退回普通衬衫、T 恤、Polo、服务制服衬衫或“上衣+裤子”的低信息组合。
- 变化矩阵标签: 用短标签标注适合的场景、情绪、身体需求、资源来源、识别强度和变化幅度。
- 设计生成语法: 记录基础款原型、设计操作、裁片路径、图案策略、工艺边界、身体适配、复杂度配额和失败规避。服装、鞋履、饰品都要能回答“哪里被加工、路径怎么走、为什么服务身体或职业”。

这些字段只描述服装结构和可复用搭配逻辑，不得变成人设、职业改写、来源故事或角色身份。

### 设计师方法引用

设计师可以作为方法来源被记录，但不能作为正式风格拷贝:

- 允许: `设计来源方法: ["平面到立体", "制作痕迹外露", "鞋履建筑结构"]`
- 条件允许: 用户明确要求测试提示词引用时，写 `设计师提示引用: ["Issey Miyake", "Maison Margiela"]`
- 禁止: `做成 Issey Miyake 风格`, `Maison Margiela 同款`, 品牌标志、专属图案、来源秀款名、设计师名替代结构描述。

如果记录 `设计师提示引用`，仍必须同时记录具体裁片路径、工艺边界、鞋履结构和复杂度控制。没有结构字段的设计师引用视为无效库存。

### 设计复杂度配额

默认配额:

```text
大形体 60%
中型裁片 25%
小工艺 10%
图案符号 5%
```

黑商入库时应明确判断复杂度是否集中在少数部位。高级设计不是全身细节平均铺开；若参考图满身随机线、满铺小纹、赛博发光线、贴图感、脏污破损或鞋底只有厚度没有结构，必须轻洗成可用结构或拒绝入库。

## 结构色块图谱

禁止把衣服简化成单一颜色，例如“上装深色、下装浅色”。黑商必须记录衣服内部的色块组织。

优先使用明度关系，不写死具体色相。可用词:

- 深值
- 中深值
- 中值
- 中浅值
- 浅值
- 高亮细线
- 高亮点缀
- 低亮硬质点缀

不要把库存色彩规则写成黑、白、灰。只有用户明确要求、或职业识别必须依赖功能色时，才写具体色相；优先写成 `警示高可见点缀`、`医疗识别点缀`、`制服秩序点缀`。

每个重要服装或单品都应包含:

```yaml
色块图谱:
  - 部位: "<衣身主面 / 肩部护片 / 胸前护板 / 袖外侧条 / 滚边线 / 扣具等>"
    明度: "<深值 / 中深值 / 中值 / 中浅值 / 浅值 / 高亮细线 / 高亮点缀 / 低亮硬质点缀>"
    面积: "<大 / 中 / 小 / 小到中>"
    位置: "<胸口正面 / 肩线外侧 / 前臂 / 腰侧 / 侧缝 / 下摆等>"
    作用: "<建立主体轮廓 / 加宽肩线 / 切分面板 / 收住轮廓 / 提供识别点等>"
```

## 饰品与小件

饰品不是可有可无的小尾巴。以下都可以入 `饰品`:

- 包具: 抱包、手持包、腰包、腿包、斜挎包、硬壳小包、背包。
- 带具: 胸背带、交叉肩带、承重带、腰封、宽腰带、腿带。
- 头颈件: 帽子、头巾、面罩、护目镜、围巾、披巾、领巾、兜帽边框。
- 手臂件: 手套、护腕、拳套、前臂护片。
- 腿部件: 护膝、腿甲、绑腿、袜套、足袋。
- 标记件: 吊牌、证件、徽章、臂章、标记片。
- 硬件件: 抽绳、拉链、扣具、金属环、挂扣、连接片。

套装货必须记录 `饰品系统`。单品货中饰品必须写 `子类` 和 `位置规则`。

## 库存隐私

回复用户时可以展示:

- `现场验货`: 原图可见内容，供用户核对。
- `正式入库`: 洗过的库存内容。

写入正式库存时只能写 `正式入库`，不得写:

- `现场验货`
- 原始文件名
- 文件路径
- 未洗过的原图分析
- 来源角色名或作品名
- 妆容、脸型、五官、肤色、皮肤质感、颜值判断

## 编码规则

所有库存文件必须是 UTF-8。正式库存允许中文，但必须保留稳定英文 `id`。

禁止写入或保留 mojibake 迹象。具体拦截样本由 `black-market/scripts/check_inventory_encoding.py` 维护，不要把乱码样本写进正式规则或库存正文。

每次写入库存后，必须运行乱码和编码检查脚本。

## 眉型、表情、姿势

眉型、表情、姿势沿用原规则:

- 眉型只写静态眉毛形状，不写眼睛、妆容、脸型、表情。
- 表情只写表演状态，不写长相、妆容、服装。
- 姿势只写身体动作、重心、手势和道具互动，不写脸和服装设计。
- 姿势库存可以包含选择用结构字段: `姿势大类`, `身体朝向`, `重心高度`, `动势强度`, `手部策略`, `展示风险`。这些字段只用于阿佐特抽选、冷却和降权，不进入最终提示词正文。

姿势正式入库使用:

```yaml
- 名称: "<中文语义名>"
  类别: "姿势"
  姿势大类: "<standing / walking / seated / crouching / kneeling / airborne / kick / fighting / lunge / leaning / shoulder_prop / turning_guard / victory / retreat / tired>"
```
